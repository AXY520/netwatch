## 任务目标

在不破坏现有 API、历史数据和懒猫 SDK 主调用链的前提下，先收口当前功能改动，再逐步提升 Netwatch 的网络变更安全性、代码可维护性、数据可信度、自动化测试、诊断能力和首页信息效率。

---

## 背景与现状

Netwatch 已不只是一个网络状态面板，而是逐渐演进为懒猫微服宿主网络控制台。目前覆盖网站连通性、出口 IPv4/IPv6、NAT、网卡实时速率、应用网桥流量、路由追踪、宽带和本机测速、LAN 设备、端口占用、通知、容器断网、网卡 IP、主机网桥、DNS 配置及自动回滚等能力。

当前工作区还包含未提交的用户改动，涉及 DNS、网络控制、应用流量方向、板块折叠、端口搜索、网站延迟布局等功能。执行本计划时必须保留这些变更，禁止通过 reset、checkout 或覆盖文件的方式回退。

### 当前主要问题

- IP、网桥、DNS 的变更确认与回滚逻辑分散，容易产生状态不一致和定时器竞态。
- SDK 或命令返回成功，只能说明请求被接受，不能证明网络真实可用。
- API 和前端核心文件职责偏重，继续叠加功能会放大回归风险。
- 应用流量的 RX/TX 视角不够直观，容易再次出现上传、下载语义误判。
- 高权限网络操作缺少完整审计、重启恢复和验证链。
- 关键前端工作流缺少浏览器级自动化回归测试。
- 首页信息较多，但“是否正常、发生了什么、数据是否新鲜”的层级还不够清楚。
- 持久化文件缺少统一 schema 版本、迁移机制和写盘健康状态。

### 重点影响范围

- 后端网络控制：`internal/probe/control_state.go`、`network_config.go`、`host_bridge*.go`、`host_dns.go`
- 后端观测与流量：`internal/probe/apptraffic*.go`、`netstats.go`、`capabilities.go`
- API：`internal/api/handler.go`、`routes.go`、`metrics.go`、`sse.go`
- 前端：`web/app-network.js`、`app-core.js`、`app-host-ports.js`、`app-settings.js`、`traffic.js`、`index.html`、`app.css`
- 构建与发布：`build.sh`、`lzc-manifest.yml`、`lzc-build.yml`

## 技术原则

- [ ] 先建立当前改动基线，再进行结构拆分或功能扩展。
- [ ] LPK 主路径继续使用懒猫 SDK，不把容器内 `nmcli` 当作默认宿主控制方案。
- [ ] 网络配置变更必须具备“申请、验证、确认、回滚、恢复、审计”完整生命周期。
- [ ] 网络变更以用户不失联为最高约束，失败时优先恢复原状态。
- [ ] API 新字段保持向后兼容，原始 RX/TX 字段和历史数据不能直接破坏。
- [ ] 延续 Go + 原生静态前端路线，不为拆分而引入 React、Vue 或新的构建链。
- [ ] 优先复用现有模块和数据文件，避免无收益的抽象、微服务和数据库迁移。
- [ ] 每个阶段必须有独立验收结果，上一阶段不稳定时不进入下一阶段。

```text
接口存在
-> 链路 connected/up
-> 地址与路由符合请求
-> 网关可达
-> DNS 可解析
-> 国内站点可达
-> 国际站点可达
-> 懒猫系统 API 可访问
```

### 清单

- [x] 为不同变更类型定义最低验证项和可选增强验证项。
- [x] 区分“配置已应用”“局部可用”“完全可用”“验证失败”。
- [x] 验证失败时保留具体步骤、耗时和原始错误，不只返回总失败。
- [x] 临时状态最多重试 4 次、间隔 500ms；外部增强验证总预算 4 秒。

- [x] 前端在现有操作输出区域展示验证状态、耗时和失败环节。
- [x] 为硬检查、可选检查、审计载荷、回滚失败和重启恢复增加测试。

- [ ] 导出前提供字段预览，避免误分享隐私。

### 完成标准

- [ ] 常见网络异常可以在应用内完成初步定位。
- [ ] 诊断数据有明确时间线，并可安全提供给维护者。
- [ ] 新能力按宿主 capabilities 渐进启用，缺失时不报假错误。

## 阶段 7：首页信息架构与数据新鲜度

**优先级：P2**  
**依赖：阶段 5；事件摘要依赖阶段 6**  
**目标：让用户先看到结论和异常，再按需查看详细指标，降低应用很多时的滚动成本。**

### 清单

- [ ] 建立“当前是否正常 -> 最近异常变化 -> 详细数据”三级结构。
- [ ] 顶部摘要使用事实状态，不引入缺少依据的 0-100 健康分。
- [ ] 摘要覆盖 IPv4、IPv6、DNS、默认出口和当前告警数。
- [ ] 所有卡片显示最近采样时间或 stale 状态。
- [ ] 刷新时保留上一次有效数据，避免整块闪空。
- [ ] 区分首次加载、刷新、空数据、权限不足、能力不支持和请求失败。
- [ ] 保留服务端持久化的整板块折叠，默认值兼顾新用户和应用较多用户。
- [ ] 检查桌面、窄屏和移动端的固定尺寸、文本换行及交互命中区域。
- [ ] 网站延迟、端口占用和应用流量采用一致的信息密度与状态表达。
- [ ] 使用现有图标库和样式系统，不制造新的视觉体系分叉。

### 建议顶部摘要

```text
网络正常 · IPv4 正常 · IPv6 正常 · DNS 正常 · 0 个告警
```

### 完成标准

- [ ] 用户无需长距离滚动即可判断当前网络是否正常。
- [ ] 数据刷新不会导致布局跳动或旧值瞬间消失。
- [ ] 桌面和移动端无文本遮挡、控制错位和横向溢出。

## 阶段 8：版本、数据迁移与持久化健康

**优先级：P2**  
**依赖：阶段 3、5**  
**目标：让版本、数据格式和写盘状态可观测，避免升级后静默损坏设置或历史数据。**

### 清单

- [ ] 增加版本 API，返回 Version、Commit、BuildTime 和 GoVersion。
- [ ] 构建脚本通过 ldflags 注入版本、提交和构建时间。
- [ ] 设置、网络事务、审计、事件和流量历史文件增加 schema version。
- [ ] 建立逐版本迁移函数，禁止用散落条件判断代替迁移链。
- [ ] 迁移前保留可恢复备份，迁移失败不覆盖原文件。
- [ ] 数据文件继续使用原子写入，记录最后成功写盘时间和最后错误。
- [ ] API 暴露 `DATA_DIR` 可写状态、磁盘空间异常和持久化降级状态。
- [ ] Prometheus 指标控制 label 基数，禁止使用应用实例、域名或错误全文作为无界 label。
- [ ] README 和发布说明记录兼容性、迁移和回滚路径。

### 建议指标

```text
netwatch_connectivity_up
netwatch_connectivity_latency_seconds
netwatch_interface_receive_bytes_total
netwatch_interface_transmit_bytes_total
netwatch_app_upload_bytes_total
netwatch_app_download_bytes_total
netwatch_network_mutation_pending
netwatch_probe_errors_total
```

### 完成标准

- [ ] 能准确确认当前运行版本及对应提交。
- [ ] 旧数据升级有自动测试，失败时可以恢复。
- [ ] 写盘异常会被界面、日志或指标明确暴露。
- [ ] Prometheus 指标不会因无界 label 导致时序爆炸。

## 风险评估

| 风险 | 可能性 | 影响 | 缓解措施 |
|---|---|---|---|
| 高权限网络操作导致用户与微服失联 | 中 | 极高 | 统一事务、最小验证链、倒计时确认、自动回滚、重启恢复 |
| SDK 调用成功但实际网络不可用 | 高 | 高 | 变更后执行链路、地址、路由、DNS和系统 API 验证 |
| timer、确认和回滚并发产生竞态 | 中 | 高 | 事务 ID、状态机锁、幂等操作、race 测试和时间模拟测试 |
| 服务重启恢复到陈旧 pending 状态 | 中 | 高 | 持久化版本、截止时间校验、目标现状复核后再恢复 |
| API 新语义字段破坏旧客户端 | 中 | 高 | 保留 RX/TX、只增不删、合约测试和版本化迁移 |
| 应用流量被误认为公网账单 | 高 | 中 | 明确 bridge 视角、内部流量边界和 host network 限制 |
| 前端拆分改变脚本加载顺序或全局状态 | 中 | 中 | 按领域小步迁移，每步做语法和浏览器回归 |
| Playwright 环境缺少 Chromium | 高 | 中 | 在 CI 和开发文档中固定安装方式及版本缓存策略 |
| 当前未提交用户改动被误覆盖 | 中 | 高 | 阶段 0 建立快照，执行前检查 diff，禁止 destructive git 命令 |
| LPK 内错误依赖容器本地 `nmcli` | 中 | 高 | 宿主控制继续走懒猫 SDK，能力探测明确 transport 来源 |
| Prometheus label 基数失控 | 中 | 高 | 预先定义有限 label 集，错误详情放日志而非 label |
| 设置或历史数据迁移失败造成数据丢失 | 中 | 高 | 原子写入、迁移前备份、失败回滚、损坏文件保留 |
| 事件采集产生大量重复数据 | 中 | 中 | 事件去重、合并、保留周期和容量上限 |
| 诊断导出泄露隐私 | 中 | 高 | 默认脱敏、字段预览、敏感字段黑名单和自动测试 |
